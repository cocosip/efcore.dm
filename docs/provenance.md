# Provenance and Licensing

This document records where code in this repository comes from. It is part of the licence record, not a development log.

## 1. Licence scope

- Original code in this repository is released under [MIT](../LICENSE).
- MIT covers original code only. Any third-party fragment, even when modified, retains its original licence and is registered in section 5.
- Anything not registered is treated as original. Self-check before committing; retroactive registration is not compliance.

## 2. Reference material

The previous implementation repository (`efcore.dm-backup`) is a **read-only reference**. It is not part of the build, no file is copied from it, and it is not a code source.

Three facts govern its use:

1. That repository's source was produced by decompiling the official `DM.Microsoft.EntityFrameworkCore` assembly and cleaning the output.
2. The official NuGet package declares **Apache-2.0** (`<license type="expression">Apache-2.0</license>`, with `requireLicenseAcceptance` set to true).
3. That source is therefore an Apache-2.0 derivative, carrying notice and change-documentation obligations. Copying whole files from it would prevent this repository from claiming MIT.

### Permitted use

| Use | Permitted |
|---|---|
| Reading it to understand Dameng dialect behaviour, such as which function maps to which SQL | Yes |
| Using it as a black-box oracle for the SQL generated by the same query | Yes |
| Deriving a list of capabilities that must be supported | Yes, because a list of facts is not an expression |
| Copying a file, or mechanically rewriting one | **No** |
| Copying comments, resource strings, or structure | **No** |

### Test for copying

A file is a copy when it is substantively isomorphic to its counterpart in the reference repository: the same private method names in the same order, the same branch structure, the same comments, or the same decompiler artifacts. Such a file is rewritten rather than cleaned.

The reason is engineering as much as licensing. The reference code carries known quality problems: `//IL_xxxx: Unknown result type` residue, `((Expression)(object)x)` casts, and wholesale copies of EF Core internal implementations. These are also defect sources, and rewriting costs less than cleaning.

## 3. EF Core

EF Core is MIT licensed and may be reused.

The strategy is to **inherit public extension points**, not to copy internal implementations:

- Allowed: deriving from `RelationalTypeMapping`, `QuerySqlGenerator`, `MigrationsSqlGenerator` and similar public base types, and calling protected virtual members.
- Allowed: reading EF Core source to understand a base type contract, and calling `base.` for the generic part.
- Avoided: copying whole EF Core internal types. Such a copy must be re-copied on every EF Core major version and is the primary source of upgrade cost.
- Exception: when copying is the only way to make something work because no extension point exists. The file header then names the source file and EF Core version, and the copy is registered in section 5.

## 4. Dameng driver

`DM.DmProvider` is a third-party ADO.NET driver supplied by Dameng. It is consumed as a NuGet dependency. Its source is not modified and not redistributed.
